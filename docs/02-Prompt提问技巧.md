# 讲义 2：Prompt 提问技巧

Vibe Coding 的成败取决于你**如何描述需求**。记住一个公式：

> **好 Prompt = 角色 + 目标 + 约束 + 验收标准**

## 1. 四要素对照表

| 要素 | 差的提问 ❌ | 好的提问 ✅ |
|------|-----------|-----------|
| 目标 | "帮我做个游戏" | "帮我做一个猜数字游戏" |
| 约束 | （无） | "用单个 HTML 文件实现，浏览器直接打开就能玩，界面用中文" |
| 细节 | （无） | "程序随机生成 1~100 的整数，玩家输入猜测后提示'大了/小了'，记录猜测次数" |
| 验收 | （无） | "猜对后显示总次数，并提供'再来一局'按钮" |

## 2. 迭代式提问模板

第一次不要贪多，先要最小可用版本，再逐步加功能：

```text
第 1 轮：请用单个 HTML 文件实现一个猜数字游戏（最小可用版本）
第 2 轮：把提示信息改成更友好的中文，猜对时显示庆祝动画
第 3 轮：增加"输入范围限制"和"非法输入提示"
第 4 轮：界面配色改成深色主题，按钮更大适合触屏
```

## 3. 报修 Bug 的正确姿势

程序出错时，把**完整报错信息 + 期望行为 + 实际行为**一起发给 AI：

```text
我在浏览器打开你生成的 index.html 后：
【期望】点击"开始"按钮后出现输入框
【实际】点击后没有任何反应
【控制台报错】Uncaught TypeError: Cannot read properties of null (reading 'addEventListener') at index.html:42
请修复这个问题，并解释错误原因。
```

> 💡 按 F12 打开浏览器开发者工具的 Console（控制台）面板，能看到报错信息——这是 Vibe Coding 必备技能。

## 4. 让 AI 解释代码

生成代码后，务必让 AI 用你能懂的方式讲一遍：

```text
请用高中生能听懂的语言，逐段解释这份代码：
1. 每个函数是做什么的？
2. 哪一行是判断"大了/小了"的核心逻辑？
3. 如果我要自己改成 1~200 的范围，需要动哪几处？
```

## 5. 红线清单（课堂纪律）

- ❌ 不上传/粘贴真实个人信息到 AI 工具
- ❌ 不让 AI 生成逃避作业的"完整成品"而不理解——验收时会要求讲解代码
- ✅ 每次迭代后运行验证，记录你用了几轮提示词
- ✅ 保留你的 Prompt 记录，作为过程性评价材料
