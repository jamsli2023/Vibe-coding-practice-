# 讲义 3：课堂实施建议

## 1. 课时安排（3 课时版）

| 课时 | 内容 | 环节 |
|------|------|------|
| 第 1 课时 | 讲义 1 + 项目 01 猜数字游戏 | 导入 10min → 演示 5min → 实操 20min → 展示 10min |
| 第 2 课时 | 项目 02 二进制转换器 | 复习 5min → 实操 25min → 代码讲解 15min |
| 第 3 课时 | 项目 03 班级数据看板 | 实操 25min → 作品互评 15min → 总结 5min |

## 2. 三维过程性评价

| 维度 | 权重 | 观测点 |
|------|------|--------|
| 需求描述质量 | 30% | Prompt 是否包含目标/约束/验收标准；是否迭代式提问 |
| 验证迭代次数 | 30% | 运行验证的主动性；报 Bug 时信息是否完整 |
| 最终作品 | 40% | 功能达成度 + 能口头讲解核心代码逻辑 |

> 验收关键动作：随机抽学生**讲解自己的代码**——能讲清楚才算掌握，防止"AI 套壳"。

## 3. 分层教学

- **基础层**：完成项目 README 中的「基础任务」，可参照提示卡
- **进阶层**：完成「挑战任务」（每个项目 README 中给出）
- **拓展层**：自选主题用 Vibe Coding 做一个解决真实生活问题的小工具

## 4. 常见问题预案

| 问题 | 处理 |
|------|------|
| 学生网络/AI 工具不可用 | 提供离线 Prompt 案例纸条，结对使用同一账号轮换操作 |
| AI 生成代码跑不起来 | 先教 F12 看控制台报错 → 用讲义 2 第 3 节模板报修 |
| 学生直接交 AI 成品 | 验收环节要求讲解代码 + 现场改一个需求 |
| 进度差异过大 | 进阶层学生担任"小教练"，讲解自己的迭代过程 |
